# 1. Цель проекта
Initiation это веб-платформа/приложение для сценаристов и креативных команд, которая объединяет простоту Markdown, совместное редактирование в реальном времени, таймлайн различных версий и возможность визуально структурировать проекты. Придерживаясь строгой структуры сценаристы смогут постепенно увеличивать масштаб  произведения, основывая его на своих собственных абстракциях(лорные узлы, арки персонажей, части сюжета) и графически строить произведение, складывая его фундамент из более мелких элементов, 
# 2 Описание системы
Система состоит из следующих основных функциональных блоков:
1. Регистриация, авторизация и аутентификация
2. Markdown поддержка
3. Timeline
4. Функционал взаимодействия с файловой системой
5. Форматирование сценариев
6. Совместное редактирование в командах
7. Визуализация произведения


### 2.1 Типы пользователей
Предполагаются разные права на уровне проекта, авторы произведения имеют полный контроль, права коллабораторов определяются автором
### 2.2 Markdown Поддержка
Интерпретатор маркадаун файлов(режим чтения, режим редактирования, предварительная отрисовка на этапе редактирования)
### 2.3 Timeline
Cистема контроля версий, настраиваемая пользователем. Визуальное отображение на прямой
#### 2.3.1 Откаты
Возможность откатиться на старую версию проекта
#### 2.3.2 Редактирование
Возможность изменить последнюю созданную версию без необходимости создавать еще одну
#### 2.3.3 Перемещение
 Беспрепятственное перемещение по версиям - сохранение локальных изменений, до создания следующей версии, чтобы пользователь мог вернуться в старую версию произведения в процессе написания и при этом не потерять свои наработки
### 2.4 Node-файловая Система
Файлы как узлы, с разными сущностями. Различные файлы будут выполнять задачу сторибилдинга, ворлдбилдинга, идей, полноценных сценариев. узлы будут связаны между собой. Блять я ебу ты мне 5 минут че то порассказывал я нихуя не понял

### 2.5 Форматирование Сценариев
Форматирование узлов, которые являются сценариями в нужном формате в соответствии с индустриальными стандартами

### 2.6 Визуальное отображение произведения
Функционал создания структуры произведения из блоков, созданных пользователем
**Пример создания мономифа**:
Автор создает файлы, являющиесся частями мономифа:
**Departure**
1. **The Ordinary World**
2. **The Call to Adventure**
3. **Refusal of the Call**
4. **Supernatural Aid**
5. **Crossing the First Threshold**
6. **Belly of the Whale**
**Initiation**
7. **The Road of Trials**
8. **Meeting with the Goddess**
9. **Woman as Temptress**
10. **Atonement with the Father**
11. **Apotheosis**
12. **The Ultimate Boon**
**Return**
13. **Refusal of the Return**
14. **The Magic Flight**
15. **Rescue from Without**
16. **Crossing the Return Threshold**
17. **Master of Two Worlds**
18. **Freedom to Live**
После этого автор использует эти блоки и связывает их между собой в хронологическом порядке и удобной для себя структуре(круговая схема или другие), внутри каждого этого файла он прописывает сценарий, мини арки, связи на другие файлы с персонажами, диалогами и т.д.
#### 2.6.1 Дерево как структура проекта
Функционал наведения на определенный блок. Пользователь может увидеть предпросмотр файла и будет иметь возможность углубиться дальше. Таким образом например из общей схемы можно будет совершить такие переходы как:
**Return**->Refusal of the return-> main character **Alan** is too afraid to go back claiming that "its not a lake its an ocean"->**Alan** Character
#### 2.6.2 Открытие файлов в разных вкладках
Функционал открытия новых вкладок при переходах в схемах
#### 2.6.3 Кастомизация схем
Пользователи смогут настраивать цветовую палитру, формы и др. визуальные решения. Также должна быть возможность добавить что то визуально для схемы не только используя, созданные пользователем узлы(например ни с чем не связанный блок заметки, или стрелочка указывающая на какой то блок)

#### 2.6.4 Доска
 Все это должно быть реализовано в формате доски, но основную часть которой, составляют узлы, созданные пользователем 
 Можно будет например написать отдельную схему для подробного ворлдбилдинга и лора, содержащую ссылки на узлы записок и документов внутри произведения и отдельную схему для сюжета, в 3-частной структуре.


### 2.7 Сценарий как отдельная сущность
В соответсвии с индустриальными стандартами сценарий будет автоматически форматироваться в формате отличном от markdown или следует реализовать кастомное форматирование на основе markdown для сценариев. Соответсвенно сценарии будут отдельными сущностями и системой будут рассматриваться иначе
